# Azure pilot deployment

`main.bicep` defines one Linux App Service (Node 22), private Azure PostgreSQL Flexible Server 16, delegated subnets and private DNS, and mandatory Entra sign-in. It is a two-user pilot: one employee and one reviewer. Claim images, ledger state and audit rows are stored in PostgreSQL. App Service reaches a configured vision provider over HTTPS; provision the provider separately. No VM, Kubernetes or GPU is required when using an external model endpoint.

1. In a sandbox subscription, choose a unique prefix and an authorized region. Register a single-tenant Entra web app. Set its redirect URI to `https://<prefix>-app.azurewebsites.net/.auth/login/aad/callback` and configure enterprise app assignment for the two pilot users. Use their Entra object IDs, rather than email addresses.
2. Pass `prefix`, `entraClientId`, `entraClientSecret`, `employeeObjectId`, `reviewerObjectId`, and `pgPassword` as secure pipeline inputs where applicable. Optionally pass `visionBaseUrl`, `visionModel`, and `visionApiKey`. Never check secrets or parameter values into git. Before a customer trial, move runtime secrets to Key Vault and give the application a least-privilege DB role.
3. Run `az bicep build --file infra/main.bicep`, then use `az deployment group what-if --resource-group <sandbox-rg> --template-file infra/main.bicep --parameters <secure-parameter-input>` to check region, SKU, networking and policy. Deploy with the same inputs using `az deployment group create`.
4. Run `npm ci && npm run build:pilot` on a Node 22 Linux runner. Stage `dist/`, `server-dist/`, `package.json`, and `package-lock.json`; run `npm ci --omit=dev` in staging, zip the staging contents, and deploy with `az webapp deploy -g <sandbox-rg> -n <prefix>-app --src-path <zip> --type zip`. The application creates the bounded pilot schema on startup.
5. Check `/healthz`; verify that an unassigned user is denied, the employee cannot approve, and the reviewer can read the original receipt. Submit competing claims near the $500 cap and verify that the limit holds. Restart the app and verify records persist. Test the chosen model using a non-sensitive webcam scene before enabling camera capture for users.

The template compiles locally. Cloud deployment, Entra login and Azure pricing have not been validated in a customer subscription. Price the selected region, runtime hours, database storage/backups and model usage separately; the $500 reimbursement limit is unrelated to Azure operating cost. The service does not post to IFS or process payments. Delete the sandbox resource group after the evaluation if retention permits.
